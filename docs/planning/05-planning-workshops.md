# Planning DISCOVER Workshops

> **Purpose:** Design workshops that create specific learning and evidence rather than generic discussion.

---

# 1. Start With the Workshop Objective

Every workshop should complete this sentence:

> **At the end of this session, we need sufficient shared understanding of ______ so that we can ______.**

Examples:

> At the end of this session, we need sufficient shared understanding of Finance capabilities and ownership so that we can identify the priority areas for deeper discovery.

> At the end of this session, we need sufficient shared understanding of the revenue-recognition decision and rules so that we can validate the information required.

If the sentence is vague, the workshop is not ready.

---

# 2. A Workshop Is an Evidence-Creation Activity

The purpose is not attendance.

The purpose is not completing an agenda.

The purpose is to create or validate useful knowledge.

Each workshop should define:

- objective;
- uncertainties;
- participants;
- relevant POPIT-V;
- technique;
- questions;
- evidence;
- artefacts;
- validation;
- exit criteria.

---

# 3. Do Not Build an Agenda First

Use this order:

```text
Objective
   ↓
Uncertainty
   ↓
Participants
   ↓
POPIT-V
   ↓
Technique
   ↓
Questions
   ↓
Agenda
```

This prevents the timetable from driving the discovery.

---

# 4. Selecting Participants

Invite people because they contribute to the objective.

Potential roles:

- outcome owner;
- capability owner;
- operational user;
- decision maker;
- SME;
- information/data owner;
- control/risk;
- technology owner;
- external partner.

Avoid filling the room with observers.

A workshop becomes harder as participant count grows.

Use interviews where depth is more valuable than group interaction.

---

# 5. Selecting POPIT-V for the Workshop

Do not cover all six by default.

Example — Finance Domain Workshop 1:

Primary:

- Organisation
- Value

Supporting:

- People

Defer detailed:

- Process
- Information
- Technology

Example — Finance Information Workshop:

Primary:

- Information
- Process

Supporting:

- Organisation

Light:

- Technology

---

# 6. Question Architecture

Group questions into three levels.

## Primary Questions

The 5–10 questions the workshop must answer.

## Probe Questions

Questions used when the answer needs depth.

## Validation Questions

Questions used to confirm the emerging understanding.

Example:

Primary:

> What are the major Finance capabilities?

Probe:

> Which capability owns forecast quality?

Validation:

> If FP&A disappeared tomorrow, would this capability still need to exist?

---

# 7. Questions Must Have a Purpose

For each question, the facilitator should know:

- what uncertainty it addresses;
- what evidence may emerge;
- where the answer will be captured.

Example:

| Question | Purpose | Artefact |
|---|---|---|
| Who approves the final forecast? | Establish decision authority | Decision Catalogue |
| What does "actual" mean here? | Establish semantic definition | Business Glossary |
| Where does this wait? | Identify process delay | Process Map / Pain Register |
| What would improve if this changed? | Establish value | Benefits Register |

---

# 8. Workshop Pattern — Domain Orientation

## Purpose

Build a shared high-level model of an unfamiliar domain.

## Duration

90–120 minutes.

## Primary POPIT-V

- Organisation
- Value
- People

## Questions

- Why does this business area exist?
- Which outcomes is it accountable for?
- What are the major capabilities?
- Who owns those capabilities?
- Which decisions matter most?
- Which processes deserve deeper investigation?
- What are the most significant problems or risks?
- Which terms or concepts cause confusion?

## Outputs

- Stakeholder Register;
- Capability Map;
- candidate decisions;
- initial pain points;
- open questions.

## Exit Criteria

The group agrees the major domain areas and where deeper discovery should focus.

---

# 9. Workshop Pattern — Process and Decision

## Purpose

Understand how work flows and where decisions, rules and exceptions occur.

## Primary POPIT-V

- Process
- People
- Information

## Questions

- What triggers the process?
- What is the required outcome?
- What are the major steps?
- Where does judgement occur?
- Who makes each decision?
- What information is required?
- Which rule applies?
- What exceptions exist?
- Where is work delayed or repeated?
- Which controls must remain?

## Outputs

- process map;
- Decision Catalogue;
- Business Rules Catalogue;
- pain points;
- evidence gaps.

---

# 10. Workshop Pattern — Information and Semantics

## Purpose

Understand concepts, definitions, KPIs, rules and information requirements.

## Primary POPIT-V

- Information

Supporting:

- Process
- Organisation
- Value

## Questions

- What are the important concepts?
- What does each mean?
- Where do definitions differ?
- Which decisions require the information?
- Which rules affect meaning?
- Who owns the definition?
- Which source is authoritative for this context?
- What lineage/provenance is required?

## Outputs

- Business Glossary;
- Business Rules Catalogue;
- Information Catalogue;
- ontology candidates;
- open questions.

---

# 11. Workshop Pattern — Validation

## Purpose

Test the current understanding.

## Questions

- What have we misunderstood?
- What is missing?
- Which statement lacks evidence?
- Which definitions conflict?
- Which Golden Thread links remain unknown?
- Which assumptions would materially change the recommendation?
- Who else must validate?

## Outputs

- validation status;
- Evidence Register updates;
- Open Question Log;
- Broken Threads;
- agreed next activity.

---

# 12. Workshop Sequence — Finance Domain Example

A useful starting sequence could be:

## Workshop 1 — Finance Context and Capabilities

Focus:

- Organisation
- Value
- People

## Workshop 2 — Finance Processes and Decisions

Focus:

- Process
- People
- Information

## Workshop 3 — Finance Information, Rules and Metrics

Focus:

- Information
- Process
- Value

## Workshop 4 — Technology / Data Constraints

Only after the business model is sufficiently understood.

Focus:

- Technology
- Information

## Workshop 5 — Validation and Opportunity

Focus:

- Value
- relevant supporting lenses.

This may be shortened or expanded based on evidence and access.

# 13. Agenda Design

A 90-minute workshop might use:

| Time | Activity |
|---:|---|
| 0–10 | Purpose, scope and known evidence |
| 10–25 | Establish context |
| 25–55 | Main discovery exercise |
| 55–70 | Decisions / information / pain |
| 70–80 | Contradictions and unknowns |
| 80–88 | Validation |
| 88–90 | Next step |

The agenda should be adapted to the technique.

---

# 14. Evidence Capture During Workshops

Capture separately:

- Evidence;
- Stakeholder Statement;
- Assumption;
- Interpretation;
- Recommendation;
- Open Question.

Do not write a clean narrative that hides disagreement.

---

## Semantic Capture During Workshops

Ontology discovery should not normally become the primary purpose of an early business workshop unless semantic modelling is the explicit discovery objective.

Instead, practise **Semantic Listening** while the main POPIT-V discussion takes place.

Semantic Listening means noticing and capturing clues about business meaning as stakeholders describe their work.

Listen for:

- important business concepts;
- relationships between concepts;
- definitions;
- synonyms and conflicting terminology;
- classifications and types;
- identifiers;
- ownership;
- business rules;
- events;
- states and status changes;
- constraints;
- exceptions;
- hierarchy;
- context-dependent meaning.

The facilitator does not need to stop the workshop to model these formally.

Use a lightweight semantic scratchpad alongside the primary workshop notes.

### Suggested shorthand

```text
[C]     Concept
[R]     Relationship
[ATTR]  Attribute
[RULE]  Business rule
[EVT]   Business event
[STATE] State / status
[SYN]   Synonym or terminology conflict
[ID]    Identifier
[OWN]   Semantic ownership
[OQ]    Open semantic question
```

Example:

```text
[C] Forecast
[C] Production
[C] Label
[C] Territory

[R] Label submits Forecast
[R] Forecast relates to Production
[R] Forecast consolidated by Territory

[STATE] Forecast: Submitted → Reviewed → Approved

[OWN] Forecast definition — FP&A?
[OQ] Is "Latest Forecast" a separate business concept or the current approved version?
```

The aim is to capture **ontology candidates**, not to produce a finished ontology during the workshop.

After the session, review the semantic scratchpad and organise useful clues into:

- Candidate Concepts;
- Candidate Relationships;
- Candidate Definitions;
- Candidate Business Rules;
- Candidate Events;
- Candidate States;
- Semantic Conflicts;
- Open Semantic Questions.

These candidates can then be validated and progressively promoted into the Business Glossary, Ontology Capture, Business Rules Catalogue or other canonical artefacts.

### Semantic trigger phrases

Certain stakeholder phrases should prompt deeper listening.

| Phrase | Possible semantic clue |
|---|---|
| "There are three types of..." | Classification / hierarchy |
| "We call it X, but they call it Y..." | Synonym or semantic conflict |
| "It depends..." | Rule or context boundary |
| "Once X happens..." | Event or state transition |
| "You can't have X unless..." | Constraint |
| "A contract can contain..." | Relationship / cardinality |
| "The system calls it..." | Difference between business meaning and system representation |
| "Technically yes, but normally..." | Exception or hidden rule |

Do not force these clues into a formal model during the conversation.

Capture them, mark uncertainty explicitly, and validate them later.

> **Early discovery captures semantic clues. Formal ontology modelling follows when there is sufficient evidence and a clear reason to model.**


---

# 15. Ending the Workshop

Always ask:

- What did we get wrong?
- What is still unknown?
- What surprised us?
- What needs evidence?
- Who needs to validate?
- What should we investigate next?

The close is part of the discovery.

---

# 16. When Not to Run a Workshop

Do not run a workshop if:

- one interview can answer the question;
- evidence already exists in a document;
- the subject is too sensitive;
- participants cannot contribute to the same question;
- the objective is unclear.

---

# 17. Workshop Quality Checklist

- [ ] Purpose sentence complete.
- [ ] Key uncertainties explicit.
- [ ] Participants selected by knowledge/authority.
- [ ] POPIT-V lenses selected.
- [ ] Technique appropriate.
- [ ] Primary questions limited.
- [ ] Every question has a purpose.
- [ ] Evidence destination known.
- [ ] Validation time included.
- [ ] Exit criteria defined.
