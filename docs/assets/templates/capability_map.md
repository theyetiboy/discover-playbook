## Naming Test

A capability should normally describe an enduring business ability.

Good examples:

- Manage Content Rights
- Forecast Financial Performance
- Manage Customer Relationships

Avoid:

- Finance Team — organisation unit
- Run Month-End — process
- Rightsline — system
- Build Customer Dashboard — project/solution

## Golden Thread Links

For priority capabilities, trace:

`STR-* → CAP-* → PRC-* → DEC-* → INF-* → BR-* → SYS/DAT-* → DP-* → ACT-* → VAL-*`

## Validation Checklist

- [ ] Capabilities are business abilities, not teams/processes/systems.
- [ ] Scope and hierarchy are proportionate.
- [ ] Definitions are clear.
- [ ] Owners are established or marked unknown.
- [ ] Strategy/value links are visible.
- [ ] Maturity judgements cite evidence.
- [ ] Cross-capability dependencies are understood.
- [ ] Capability map has been validated with relevant stakeholders.
