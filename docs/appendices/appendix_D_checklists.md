# Appendix D — DISCOVER Practitioner Checklists

> Checklists support discipline; they do not replace judgement.

---

# 1. Engagement Readiness Checklist

- [ ] Business problem/outcome stated without assuming a solution.
- [ ] Sponsor / outcome owner identified.
- [ ] Scope and exclusions explicit.
- [ ] Initial stakeholder landscape created.
- [ ] Existing evidence identified.
- [ ] Known constraints documented.
- [ ] Current assumptions visible.
- [ ] Success / value measures considered.
- [ ] Discovery approach proportionate to the problem.
- [ ] No platform/product commitment has been mistaken for a requirement.

# 2. Define Checklist

- [ ] Why now understood.
- [ ] Strategic link identified.
- [ ] Business outcome defined.
- [ ] Scope bounded.
- [ ] Key stakeholders known.
- [ ] Desired discovery outputs clear.
- [ ] Risks/dependencies captured.
- [ ] Initial evidence confidence understood.
- [ ] Sufficient confidence to investigate.

# 3. Investigate Checklist

- [ ] Domain/capability landscape explored.
- [ ] Stakeholder map broadened.
- [ ] Existing terminology reviewed.
- [ ] Processes/reports/systems inventoried at useful level.
- [ ] Known decisions identified.
- [ ] Evidence sources catalogued.
- [ ] Hotspots/pain hypotheses visible.
- [ ] Important missing perspectives identified.

# 4. Study Checklist

- [ ] Priority areas selected based on value/evidence.
- [ ] Actual process understood, including exceptions.
- [ ] Decision owners and triggers identified.
- [ ] Information requirements captured.
- [ ] Business rules explored.
- [ ] Ownership/governance understood.
- [ ] Technology constraints mapped after business context.
- [ ] Value impact investigated.
- [ ] Root cause distinguished from symptom where possible.

# 5. Capture Checklist

- [ ] Raw evidence preserved.
- [ ] Evidence classifications used.
- [ ] Stable IDs used where justified.
- [ ] Conflicts visible.
- [ ] `UNKNOWN` used instead of invented answers.
- [ ] Definitions linked to owners/evidence.
- [ ] Decisions, rules and pain points recorded.
- [ ] Personally/sensitive information handled appropriately.

# 6. Organise Checklist

- [ ] Findings structured using relevant POPIT-V lenses.
- [ ] Capability/process/decision concepts not conflated.
- [ ] Golden Thread relationships built where supported.
- [ ] Broken Threads explicit.
- [ ] Ontology/glossary conflicts organised by context.
- [ ] Artefacts cross-reference evidence.
- [ ] Duplicate records reconciled without losing provenance.

# 7. Validate Checklist

- [ ] Right validators identified.
- [ ] Findings presented as current understanding, not fact by assertion.
- [ ] Conflicting perspectives reviewed.
- [ ] Rules/definitions validated by appropriate owners.
- [ ] Key assumptions tested.
- [ ] Process validated by people who perform it.
- [ ] Golden Thread gaps reviewed.
- [ ] Validation status updated.

# 8. Evaluate Checklist

- [ ] Root causes supported by evidence.
- [ ] Business impact understood.
- [ ] Value and cost of inaction considered.
- [ ] Risks/controls considered.
- [ ] Opportunities solution-neutral where appropriate.
- [ ] Dependencies visible.
- [ ] Maturity assessed separately across POPIT-V where useful.
- [ ] Quantitative precision not invented.
- [ ] Alternatives considered.

# 9. Roadmap Checklist

- [ ] Roadmap is outcome-led.
- [ ] Each item links to evidence/problem.
- [ ] Capability/decision/process context included.
- [ ] Value measure included.
- [ ] Dependencies explicit.
- [ ] Validation needs explicit.
- [ ] Now/Next/Later used unless real dates are known.
- [ ] Delivery estimates not invented.
- [ ] Discovery roadmap not confused with sprint/release plan.

# 10. Workshop Checklist

## Before
- [ ] Objective.
- [ ] Participants.
- [ ] Agenda/timebox.
- [ ] Relevant POPIT-V lenses only.
- [ ] Questions.
- [ ] Evidence capture.
- [ ] Validation close.

## During
- [ ] Neutral facilitation.
- [ ] Concrete examples.
- [ ] Exceptions.
- [ ] Conflicts.
- [ ] Decisions/information/rules.
- [ ] Parking lot.
- [ ] Value.

## After
- [ ] Notes secured.
- [ ] Evidence register updated.
- [ ] Artefacts updated.
- [ ] Open questions assigned.
- [ ] Next step communicated.

# 11. Data Product Readiness Checklist

- [ ] Clear consumer.
- [ ] Decision/action supported.
- [ ] Business concepts governed.
- [ ] Quality/freshness expectations defined.
- [ ] Data ownership known.
- [ ] Product ownership known.
- [ ] Access/security understood.
- [ ] Service expectations understood.
- [ ] Adoption measure defined.
- [ ] Business value measure defined.
- [ ] Product is more than a renamed table/report.

# 12. AI Opportunity Readiness Checklist

- [ ] Evidenced problem.
- [ ] User task clear.
- [ ] AI capability appropriate.
- [ ] Required information available or gaps known.
- [ ] Provenance/grounding considered.
- [ ] Human oversight defined.
- [ ] Privacy/security/IP risks considered.
- [ ] Evaluation metrics defined before build.
- [ ] Non-AI alternatives evaluated.
- [ ] Value measure defined.
- [ ] Failure/rollback/escalation considered.

# 13. Ontology Readiness Checklist

- [ ] Competency questions.
- [ ] Business concepts.
- [ ] Definitions.
- [ ] Context/bounded contexts.
- [ ] Relationships.
- [ ] Rules/constraints.
- [ ] Identity.
- [ ] Provenance.
- [ ] Owners.
- [ ] Source mapping separated from semantics.
- [ ] Governance/versioning.
- [ ] Scope driven by use/value.

# 14. Evidence Quality Checklist

For a material finding ask:

- [ ] What is the source?
- [ ] Is the source current?
- [ ] Is the source authoritative for this context?
- [ ] Has it been corroborated?
- [ ] Is it direct evidence or stakeholder statement?
- [ ] Does conflicting evidence exist?
- [ ] What confidence should we assign?
- [ ] Who can validate?
- [ ] What decision would change if this were wrong?

# 15. Executive Readout Checklist

- [ ] Why we investigated.
- [ ] What we learned.
- [ ] Evidence.
- [ ] Business impact.
- [ ] Broken Threads / unknowns.
- [ ] Value.
- [ ] Decisions required.
- [ ] Recommended next discovery action.
- [ ] No unsupported solution claims.
- [ ] Detail linked, not overloaded into slides.
