# Wardley Mapping

> *"Strategy improves when we make the landscape, dependencies and assumptions visible enough to challenge."*

## Purpose

Wardley Mapping is a strategic mapping technique associated with Simon Wardley. It maps a value chain against the evolution of its components, anchored in user need.

DISCOVER uses Wardley Maps selectively to explore strategic context, dependency and make/buy/evolve questions—not as a universal discovery artefact.

## Core Axes

A Wardley Map combines:

### Visibility / Value Chain
How close a component is to the user need.

### Evolution
How mature or commoditised a component is, commonly considered from:

1. Genesis;
2. Custom Built;
3. Product / Rental;
4. Commodity / Utility.

The positions are **strategic judgements**, not precise measurements.

## Why This Matters

Technology and data teams can spend significant effort custom-building capabilities that are undifferentiated, while underinvesting in strategically important domain knowledge.

Wardley Mapping can help challenge:

- build vs buy;
- platform investment;
- differentiation;
- dependency;
- inertia;
- future movement.

## How It Fits DISCOVER

Most useful during:

- Define;
- Investigate;
- Evaluate;
- Roadmap.

It is less useful for detailed operational process discovery.

## When to Use It

Use when:

- strategic options are unclear;
- a capability contains both differentiating and commodity components;
- build/buy/platform choices matter;
- future movement of capabilities affects roadmap;
- leadership needs to see dependencies.

## When Not to Use It

Avoid when:

- there is no clear user need;
- the immediate question is operational;
- participants treat positions as objective scores;
- the map would substitute opinion for evidence.

## Suggested Approach

### 1. Identify the User and Need

Without an anchored need, the map becomes a technology inventory.

### 2. Build the Value Chain

Ask:

- What must exist for that need to be met?
- What does each component depend on?

### 3. Position by Evolution

Discuss:

- novelty;
- certainty;
- market availability;
- standardisation;
- operational characteristics.

### 4. Expose Assumptions

Mark uncertain positions.

### 5. Explore Movement

Which components are evolving? What might become commodity?

### 6. Discuss Strategic Options

Examples:

- differentiate;
- standardise;
- outsource;
- build platform capability;
- reduce dependency;
- exploit a changing market.

## Data / Analytics Example

Suppose the user need is:

> A Sales executive can confidently identify the strongest content opportunity for a customer.

Components might include:

- domain-specific content/customer relationship insight;
- semantic model;
- governed data products;
- identity/access;
- cloud storage/compute.

The cloud infrastructure may be commodity while domain semantics remain differentiating.

This discourages spending strategy time reinventing commodity components.

## Finance Example

A Finance map might contrast:

- accounting-specific business rules and commercial model knowledge;
- forecasting logic;
- enterprise data integration;
- generic cloud compute;
- commodity collaboration tooling.

## Marketing Example

A Marketing map may show:

- differentiated audience strategy;
- platform-specific activation;
- analytics capability;
- generic storage/compute;
- external media platforms.

## Wardley Mapping and Capability Mapping

Capability Mapping answers:

> What must the organisation be able to do?

Wardley Mapping asks:

> What components make the user need possible, how do they depend on one another, and how evolved are they?

The techniques complement one another.

## Evidence

Treat every map position as an **interpretation** unless supported by external/market evidence.

Record:

- rationale;
- evidence;
- confidence;
- assumptions.

Do not present a Wardley Map as an objective fact.

## Outputs

- Wardley Map;
- Strategic Assumption Log;
- Build/Buy questions;
- Dependency insights;
- Roadmap hypotheses;
- Investment discussion.

## Common Pitfalls

- mapping systems rather than user need;
- treating evolution as a precise score;
- arguing about position instead of strategic implication;
- using the map to justify a decision already made;
- assuming custom build is inherently more valuable;
- using it where simple capability/process analysis is enough.

## Practitioner Checklist

- [ ] User and need are explicit.
- [ ] Value-chain dependencies are visible.
- [ ] Evolution positions have rationale.
- [ ] Uncertainty is marked.
- [ ] Map supports a strategic decision.
- [ ] Commodity vs differentiating assumptions are challenged.
- [ ] Output feeds evaluation/roadmap rather than becoming decoration.

Wardley Mapping gives DISCOVER a strategic lens for user need, dependency and evolution. It is most valuable when used to challenge assumptions about where differentiation and investment really belong.
