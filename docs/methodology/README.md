# DISCOVER Canonical Methodology

This directory contains the **authoritative definition of the DISCOVER methodology**.

## Source-of-Truth Rule

The following files are canonical:

- `discover-framework.md` — lifecycle, operating model and overall methodology
- `discover-principles.md` — behavioural principles
- `popit-v-overview.md` — analytical lens
- `golden-thread.md` — business-to-value traceability model
- `maturity-model.md` — maturity model

Other parts of the repository are derived representations:

- `docs/chapters/` provides practitioner-friendly guidance;
- `docs/assets/templates/` provides operational artefacts;
- `core/` provides an AI-optimised summary and operating instructions;
- `prompts/` provides domain-specific conversation starters.

If a derived file conflicts with this directory, **the canonical methodology takes precedence**.

## Change Control

When the canonical methodology changes:

1. update the relevant file in this directory;
2. review affected practitioner chapters;
3. review affected templates;
4. review `core/00-DISCOVER-Core.md`;
5. review `core/01-Notebook-Operating-Instructions.md`;
6. review domain prompts where behaviour or terminology has changed.

This keeps the methodology, handbook and AI toolkit aligned.

## Core Consistency Rules

All derived material should preserve the following:

- DISCOVER is iterative, not a rigid waterfall;
- progress is based on sufficient confidence, not perfect certainty;
- validation occurs continuously;
- POPIT-V is an analytical lens, not a checklist that every workshop must exhaust;
- decisions drive data requirements;
- evidence must be distinguished from assumption and interpretation;
- the Golden Thread provides traceability from strategy to value;
- DISCOVER is not a delivery lifecycle;
- roadmaps are outcome-led direction, not detailed release schedules;
- candidate solutions may emerge during discovery, but should not be treated as requirements until supported by evidence;
- every recommendation should connect to measurable business value.

## Terminology

Use the terminology defined in the canonical files consistently.

Where a new concept is introduced, prefer adding it to the canonical methodology first and then propagating it into chapters, templates and AI instructions.
